# 小米笔记同步工具

小米笔记里攒了几年的内容，真正想备份时，往往要逐篇复制或分享。笔记少还好；一旦有几百条，分类、标题、图片和录音很容易在导出后散成一地。

网上能找到一些导出方案，但常见的麻烦也很实际：有的只拿到文字，有的把附件堆进同一个文件夹，还有的需要手动找 Cookie。导出完成之后，反而得花时间重新整理。

这个工具把重点放在“导出后还能继续用”上：按原分类落盘、保留正文里的图片和音频位置、给每篇笔记单独存附件，并在后续同步时跟随云端的改名、移动和删除。

把小米云笔记导出为电脑上的 Markdown 文件。笔记会按小米笔记里的分类放进对应文件夹，图片和音频会留在它们原本所在的正文位置。

这是一个独立的 Windows 桌面工具，不需要安装 Obsidian。它只把小米云内容同步到本地；本地修改不会回写到小米云。

## 怎么用

1. 打开程序，先选择服务区域。中国大陆账号选 i.mi.com；海外账号选 us.i.mi.com。切换区域会退出当前账号。
2. 点击“登录小米账号”，在弹出的官方登录窗口完成登录。
3. 选择一个导出文件夹。建议新建一个空文件夹专门存放导出的笔记。
4. 需要让本地跟随云端的分类移动和删除时，保留“同步云端移动与删除”开关开启。
5. 点击“开始同步”。第一次会下载全部内容，后续只处理有变化的笔记。

同步完成后，界面会显示本次写入、未变化、移入回收区和失败的数量。右上角的刷新按钮会强制重新下载全部笔记。

## 导出后的文件

假设你把内容导出到 D:\Notes\Xiaomi，目录大致如下：

~~~text
D:\Notes\Xiaomi\
+-- 工作\
|   +-- 项目计划_10000000000000001.md
|   +-- .assets\
|       +-- 10000000000000001\
|           +-- image-1.jpg
+-- 随笔\
+-- 待办事项\
+-- .minote-sync\
    +-- state.json
    +-- trash\
~~~

- 分类会变成本地文件夹；小米笔记没有分类时，文件保存在导出根目录。
- Markdown 文件优先使用笔记标题。遇到同名笔记，文件名会附带小米笔记 ID，避免相互覆盖。
- Windows 不允许的文件名字符会替换为对应的全角字符。
- 每篇笔记的附件保存在同分类下的 .assets/<笔记 ID>/。Markdown 中的图片和音频引用指向这里，不会混成一个难以辨认的大文件夹。
- .minote-sync/state.json 是同步记录，不是笔记正文。不要手动编辑它。

## 移动、删除与保护规则

开启“同步云端移动与删除”后：

- 在小米笔记里改标题或移动分类，本地文件会随之改名或移动。
- 在小米笔记里删除笔记，本地文件不会直接消失，而是移到 .minote-sync/trash/，可以手动找回。
- 云端列表为空、分页异常、单篇同步失败，或本次预计删除的数量异常时，工具会停止清理，避免误删本地文件。
- 不属于本工具管理范围的 Markdown 文件不会被移动或删除。

关闭这个开关时，工具仍会下载新内容和更新已有内容，但不会根据云端删除或分类移动清理本地文件。

## 隐私

登录 Cookie 只保存在应用自己的数据目录里，并由 Electron safeStorage 加密。Cookie 不会写入导出文件夹、Git 仓库或界面。

发布项目或分享导出文件夹前，请检查其中是否有真实笔记、附件、账号信息，尤其不要提交 .minote-sync、小米账号配置或从旧 Obsidian 插件复制出的 data.json。

## 安装与运行

Windows 发布页会提供两种文件：

- setup.exe：安装版。默认安装到当前用户目录，可从 Windows 设置的“已安装的应用”卸载。
- portable.exe：便携版。无需安装，适合放在移动硬盘或临时使用。

当前发行包未做代码签名，因此 Windows SmartScreen 可能会显示“未知发布者”提示。

## 本地开发

需要 Node.js 22 或更高版本。

~~~powershell
npm install
npm run dev
~~~

常用检查与构建命令：

~~~powershell
npm test
npm run typecheck
npm run lint
npm run build
npm run build:win
~~~

Windows 构建产物会出现在 dist 目录。推送形如 v0.1.0 的 Git 标签后，GitHub Actions 会构建安装版和便携版，并把它们附加到对应 Release。
